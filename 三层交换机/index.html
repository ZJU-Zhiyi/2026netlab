    选做实验：使用三层交换机组网

    注意

    本实验为选做内容，不计入课程成绩(无附加分)，同学们可以根据自身情况自行探索。

    实验模板及工具网站：http://10.214.0.253/network/download/（本实验的实验模板对应网站上Lab3）

    本实验分别使用路由器单臂路由和三层交换机 SVI，实现 VLAN 10 与 VLAN 20 之间的 IP 转发。两种方案使用相同的网关地址规划，便于比较结果。

    1 实验目标

    • 配置 VLAN、Access 端口和 Trunk 链路。
    • 使用路由器子接口和 802.1Q 标签实现 VLAN 间路由。
    • 使用三层交换机 SVI 和 IP routing 实现 VLAN 间路由。
    • 验证网关可达、同 VLAN 跨交换机通信和跨 VLAN 通信。
    • 根据接口状态、Trunk 状态和路由表排查连通性问题。

    2 环境与地址规划

    准备一台二层交换机 S1、一台支持 802.1Q 子接口的路由器 R1、一台支持 SVI 路由的三层交换机 S2，以及最多四台测试 PC。第一阶段使用 S1、R1、PC1、PC2；第二阶段移除 R1，加入 S2、PC3、PC4。可使用课程提供的实体设备或支持所需功能的隔离模拟环境。Console 连接和 PC 静态地址设置按操作系统与设备说明完成。

    实验统一使用以下地址规划。两个 VLAN 属于不同子网，各自的网关均为 .1 地址；单臂路由阶段由 R1 子接口提供网关，三层交换阶段由 S2 的 SVI 提供网关。

    2.1 地址规划

    设备 阶段 接口 VLAN IPv4 地址/掩码 默认网关
    PC1 两阶段 S1 Fa0/1 10 10.0.10.11/24 10.0.10.1
    PC2 两阶段 S1 Fa0/2 20 10.0.20.12/24 10.0.20.1
    R1 子接口 第一阶段 Gi0/0.10 10 10.0.10.1/24 不适用
    R1 子接口 第一阶段 Gi0/0.20 20 10.0.20.1/24 不适用
    PC3 第二阶段 S2 Fa0/1 10 10.0.10.13/24 10.0.10.1
    PC4 第二阶段 S2 Fa0/2 20 10.0.20.14/24 10.0.20.1
    S2 SVI 第二阶段 VLAN 10 10 10.0.10.1/24 不适用
    S2 SVI 第二阶段 VLAN 20 20 10.0.20.1/24 不适用

    本指南命令按 Cisco IOS/Catalyst 风格书写，假设 S1 的 Fa0/1、Fa0/2 接入 PC，Gi0/1 为上联；S2 的 Fa0/1、Fa0/2 接入 PC，Gi0/1 连接 S1；R1 的 Gi0/0 连接 S1。若实际接口不同，先替换所有命令中的接口名称。设备型号、IOS 版本及模拟模块对 Trunk、SVI 和路由功能的支持可能不同。不要在共享或生产网络上更改配置。

    实验记录：填写本组设备型号、阶段一和阶段二的实际拓扑、接口对应关系及与地址规划不一致之处；后续记录均以本组实际端口和配置为准。

    3 第一阶段：路由器单臂路由

    3.1 建立拓扑

    连接 PC1、PC2 和 R1 到二层交换机 S1。PC1、PC2 分别接入 VLAN 10、20；S1 与 R1 之间用一条 Trunk 链路。R1 的 Gi0/0 物理接口划分为 Gi0/0.10 和 Gi0/0.20 两个子接口，分别作为两个 VLAN 的网关。

    通过 Console 登录 S1 和 R1。若提示符为 设备名>，先输入 enable，按要求认证并进入提示符为 设备名# 的特权 EXEC 模式；后续配置命令均从该模式开始执行。修改配置前，执行 show running-config，将本实验涉及的原有配置输出保存到本组记录中，并记录设备和接口的初始状态。第二阶段配置 S2 前也需完成同样的检查与备份。

    3.2 配置 S1

    创建 VLAN 10、20，配置连接 PC 的 Access 端口，并把连接 R1 的 Gi0/1 配置为允许两个 VLAN 的 Trunk：

    configure terminal
vlan 10
 name VLAN10
vlan 20
 name VLAN20
interface fastEthernet 0/1
 switchport mode access
 switchport access vlan 10
 no shutdown
interface fastEthernet 0/2
 switchport mode access
 switchport access vlan 20
 no shutdown
interface gigabitEthernet 0/1
 switchport mode trunk
 switchport trunk allowed vlan 10,20
 no shutdown
end
show vlan brief
show interfaces trunk

    确认 PC1、PC2 端口分别属于 VLAN 10、20，并检查 Gi0/1 已配置为 Trunk、允许 VLAN 10、20。此时 R1 接口可能尚未启用，Trunk 的实际运行状态在 3.3 节完成 R1 配置后再确认。部分型号需先指定 switchport trunk encapsulation dot1q，再执行 switchport mode trunk；若设备不支持前一条命令，按设备手册确认默认封装和配置方式。

    实验记录：保存 show vlan brief 的关键输出，注明 PC 接入口 VLAN 和已配置的 Trunk 允许列表；Trunk 运行状态在下一节记录。

    3.3 配置 R1 子接口

    R1 的父接口不配置 IP 地址；两个网关地址配置在子接口上。子接口编号用于区分逻辑接口，实际 VLAN 由 encapsulation dot1Q 后的 VLAN ID 指定：

    configure terminal
interface gigabitEthernet 0/0
 no ip address
 no shutdown
interface gigabitEthernet 0/0.10
 encapsulation dot1Q 10
 ip address 10.0.10.1 255.255.255.0
interface gigabitEthernet 0/0.20
 encapsulation dot1Q 20
 ip address 10.0.20.1 255.255.255.0
end
show ip interface brief
show ip route

    确认物理接口和子接口处于可用状态，路由表包含 10.0.10.0/24、10.0.20.0/24 两条直连路由。若接口名或命令不受设备支持，先查阅该型号帮助，不要照搬不兼容配置。

    回到 S1 执行 show interfaces trunk，确认 Gi0/1 已处于 Trunk 状态，且 VLAN 10、20 均可通过。

    实验记录：记录 R1 物理接口、子接口状态及两条直连路由，保存 S1 的 Trunk 运行状态；若状态或路由与预期不符，先记录现象再排查。

    3.4 配置 PC 并验证

    按第一阶段地址表配置 PC1、PC2 的地址、/24 掩码和默认网关。依次进行以下测试并记录结果：

    1. PC1 ping 10.0.10.1，PC2 ping 10.0.20.1，验证各自网关可达。
    2. PC1 ping PC2 的 10.0.20.12，验证 R1 能在 VLAN 10、20 之间转发。

    成功时，PC1 发往 PC2 的流量先到达 VLAN 10 网关；R1 根据路由表从 VLAN 20 子接口转发，再由 S1 送至 PC2。Trunk 携带带标签的 VLAN 流量，本身不执行 IP 路由。

    实验记录：逐项填写两台 PC 到网关及跨 VLAN ping 的预期和实测结果，并记录未达预期时的排查步骤。若排查中修改了配置，更新上一节对应的状态记录。

    4 第二阶段：三层交换机路由

    4.1 调整拓扑

    完成并记录第一阶段后，断开并移除 R1，避免 VLAN 10、20 出现重复的 .1 网关地址。保留 S1 和 PC1、PC2；加入 S2、PC3、PC4。PC1、PC3 属于 VLAN 10，PC2、PC4 属于 VLAN 20；S1 与 S2 之间使用一条 Trunk。

    实验记录：确认 R1 已断开，记录阶段转换时保留/移除的设备与链路，并核对当前网络中 .1 网关的唯一归属。

    4.2 复用 S1 配置

    保留第一阶段在 S1 上配置的 VLAN 10、20 和 PC Access 端口。断开 R1 后，将原上联 Gi0/1 改接到 S2，并检查本端保留的 Trunk 配置允许 VLAN 10、20。本阶段不必重复配置 S1 的 PC 接入口；两端 Trunk 的运行状态在 4.3 节完成 S2 配置后再确认。

    实验记录：记录 S1 复用的 VLAN、接入口配置及上联对应关系；若为适配设备调整了配置，注明调整内容。

    4.3 配置 S2 三层交换机

    在 S2 创建 VLAN 10、20，将 PC3、PC4 端口配置为对应的 Access VLAN；将与 S1 相连的 Gi0/1 配置为 Trunk；创建两个 SVI 并启用 IP 路由：

    configure terminal
vlan 10
 name VLAN10
vlan 20
 name VLAN20
interface fastEthernet 0/1
 switchport mode access
 switchport access vlan 10
 no shutdown
interface fastEthernet 0/2
 switchport mode access
 switchport access vlan 20
 no shutdown
interface gigabitEthernet 0/1
 switchport mode trunk
 switchport trunk allowed vlan 10,20
 no shutdown
interface vlan 10
 ip address 10.0.10.1 255.255.255.0
 no shutdown
interface vlan 20
 ip address 10.0.20.1 255.255.255.0
 no shutdown
ip routing
end
show vlan brief
show interfaces trunk
show ip interface brief
show ip route

    本阶段要求设备支持通过 SVI 执行 VLAN 间路由，并支持启用 ip routing。仅支持管理 SVI 的二层交换机不能完成本阶段的路由任务。SVI 要达到 up/up，VLAN 必须存在，SVI 不能被关闭，且 VLAN 中通常需至少有一个活动并处于 STP 转发状态的二层端口。若设备不支持所需路由功能，应使用课程指定的三层交换设备。

    完成 S2 配置后，在 S1、S2 上分别执行 show interfaces trunk，确认互联端口均处于 Trunk 状态，并允许 VLAN 10、20。

    实验记录：记录 S2 的两个 SVI 状态和地址、路由表中的直连网段，以及两端 Trunk 的运行状态；若状态与预期不符，记录排查结果。

    4.4 配置 PC 并验证

    保持 PC1、PC2 的地址和网关不变。新增 PC3：10.0.10.13/24、网关 10.0.10.1；PC4：10.0.20.14/24、网关 10.0.20.1。

    网关 IP 沿用第一阶段的地址，但提供网关的设备已从 R1 更换为 S2，PC1、PC2 可能仍缓存原网关的 MAC 地址。测试前检查并清除两台 PC 各自网关的旧 ARP/邻居条目，使主机重新解析当前网关的 MAC 地址。Windows 可在管理员终端用 arp -a 查看，PC1 执行 arp -d 10.0.10.1，PC2 执行 arp -d 10.0.20.1；Linux 可用 ip neigh 查看，并执行 sudo ip neigh del <网关地址> dev <网卡名> 删除对应条目。缓存中没有对应条目时可直接继续。

    确认 S2 两个 SVI 为 up/up，路由表包含两个直连子网后，按顺序测试：

    1. 四台 PC 分别 ping 自己的默认网关。
    2. 测试同 VLAN、跨交换机通信：PC1 ping PC3，PC2 ping PC4。
    3. 测试跨 VLAN 通信：PC1 ping PC4，PC2 ping PC3。

    可选对照：在隔离环境中临时从 S1-S2 Trunk 的 allowed VLAN 列表移除一个 VLAN，观察该 VLAN 的远端主机无法到达网关或同 VLAN 对端；随后立即恢复并重测。不要把临时错误配置留在最终状态。

    实验记录：分别填写第二阶段的网关、同 VLAN 跨交换机和跨 VLAN ping 结果，注明每项涉及的设备与地址，并记录网关 ARP/邻居条目的检查及更新情况。若完成可选对照，记录移除/恢复 VLAN 前后的现象；若排查中修改了配置，更新上一节对应的状态记录。

    故障排查与恢复

    • PC ping 不通网关：核对 PC 的 IP、掩码、网关、Access VLAN、物理链路以及路由器子接口/SVI 状态。
    • 同 VLAN 跨交换机不通：确认两端都创建该 VLAN，Trunk 两端均 up 且允许该 VLAN，STP 端口处于 Forwarding。
    • SVI 为 down/down：检查 VLAN 是否存在、SVI 是否 shutdown，以及 VLAN 中是否有活动且处于 STP 转发状态的端口。
    • 网关可达但跨 VLAN 不通：检查子接口/SVI 地址、路由器或三层交换机是否启用转发，并查看路由表。
    • ping 起始有丢包：检查 ARP 邻居解析、接口状态和 STP 收敛；确认主机防火墙允许实验网中的 ICMP。不要因单次失败就直接关闭整台防火墙。

    实验结束后恢复开始前记录的配置，移除测试时创建的临时路由器或临时设置，确认网络中只有当前方案指定的 VLAN 网关，避免两个设备同时使用同一网关地址。

    说明

    不同平台的命令可能不同，可参考设备对应软件版本的 Cisco 指南：Catalyst VLAN 间路由配置。
